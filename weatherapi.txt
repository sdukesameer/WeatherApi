Thank you, I'd like to walk you through Skyline, a weather dashboard I built on top of the OpenWeather API. It shows the current conditions, air quality, a sunrise-to-sunset tracker, and a 5-day forecast for any city the user searches, or for their current location.

I built it with plain HTML, CSS and JavaScript, deliberately without a framework, so I could focus on getting the fundamentals — DOM structure, state, and API composition — right. When a user searches, I call OpenWeather's Geocoding API to resolve the city name to a latitude/longitude pair, with a debounced autocomplete dropdown so results update as they type without hammering the API on every keystroke. Once I have coordinates, I fire the current weather, forecast, and air pollution requests together with Promise.all instead of chaining them, since none of them depend on each other's results.

One feature I'm proud of is that the UI actually reacts to the data instead of just displaying it. Each condition returned by the API — clear, clouds, rain, thunderstorm, snow, mist — maps to a theme key that I set as a data attribute on the body element. CSS custom properties do the rest, so the background gradient and glass tint shift automatically, and I layer a canvas animation on top for rain, snow, or a twinkling night sky, driven by that same condition key.

The sunrise-to-sunset widget is a small piece of math I enjoyed working out: I take the current timestamp, sunrise, and sunset from the API, compute how far through the day we are as a percentage, and place a dot along an SVG arc at that percentage using getPointAtLength, so it's a genuinely accurate read of the time of day rather than a static icon.

The forecast endpoint on the free tier only returns data in 3-hour steps, so for the 5-day view I group those slots by local calendar day using the city's UTC offset, and pick the slot closest to 1pm as the representative reading for that day. The hourly strip just shows the next 8 of those 3-hour steps directly.

Finally, I persist the user's unit preference and their last few searched cities in localStorage, and I handle failure states properly — a loading skeleton while requests are in flight, and a clear error banner if a city can't be found or geolocation is denied, rather than a silent alert like my first version had.
